## Gaps and ordered migration

1. **Preserve the current release.** Keep schema version 1, IDs, published claims, and public PDF unchanged while private review is underway. Record the actual served artifact hash only when it can be fetched; do not infer it from a fresh build, whose PDF metadata may vary.
2. **Resolve the private source record.** Review candidate claims and supporting material, individual contributions, contested dates, titles, affiliation, outcomes, and skill depth. Keep a private crosswalk to existing public IDs and a per-audience owner decision. This is a prerequisite to claiming a comprehensive master or changed baseline.
3. **Design the next schema and selectors.** Specify stable IDs for roles, projects, claims, and skills; chronology; evidence/review state; sensitivity; audience wording; and public-safe links. Decide how a profile or target selects verified IDs for a posting. Add fail-closed validation, migration tests, and compatibility handling before moving facts. The current public renderer must remain self-contained.
4. **Build the owner-only master privately.** Render a browsable, claim-addressable résumé/CV from the reviewed private record, with no page cap. Keep source evidence and PDFs out of this repository, CI artifacts, and Pages. If a shared rendering component is needed, it must accept only an explicitly provided local/private input and never cause public CI to fetch that input.
5. **Review the generic baseline separately.** Use the existing two-page public résumé as the visual/application starting point. Select approved facts, broaden skills only at their verified depth, then inspect both application and sanitized public renders with Alan before changing `general` or the published PDF. Contact values remain in the ignored local overlay.
6. **Prove tailoring and release.** For a real, active posting, select approved claim IDs and keep its private evidence/selection manifest with the packet. Render résumé/CV/cover letter as required without editing the canonical claim to match the ad. Run fact/schema, profile, privacy, test, ATS/PDF extraction, links, and visual checks. Record owner review and submission status separately from document preparation.

Checkpoint 1 ends with this inventory and versioned boundary. Checkpoints 2–6 remain open. No private-to-public migration, source claim approval, new master renderer, baseline replacement, or Pages release is part of this PR.
